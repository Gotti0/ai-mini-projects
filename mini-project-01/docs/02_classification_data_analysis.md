- **수치형 특성 분포의 특징(`ProductRelated`, `PageValues` 등):** 멱분포를 닮았다.

**분석:** 모두 미구매로 예측했을 때 Accuracy가 약 84.53%인 이유와 이 수치만으로 평가하기 어려운 점을 작성합니다.  
미구매가 전체의 84.53%이기 때문에 분류를 전부 미구매라고 답하는 모델에 넣으면 정확도가 84.53%가 나온다. 이 수치만으로는 평가하기 힘들다. 구매를 구매라고 말한 재현율이 0%가 나오기 때문이다.

## 2. 계층화 데이터 분할 (CP-02)

- **Train:** 8630건 / 구매 비율 15.48%
- **Validation:** 1850건 / 구매 비율 15.46%
- **Test:** 1850건 / 구매 비율 15.46%
- **`stratify`를 적용한 이유:** 각 데이터 분할에 같은 구매 비율을 유지하기 위해서이다.
- **1일차 회귀의 날짜 순서 분할과 다른 이유:** 1일차에서는 미래 참조 편향을 막기 위하여 날짜 순서 분할을 사용하였다. 2일차에서는 구매 비율이 불균형이므로 각 분할에 비슷한 구매 비율을 유지하기 위해 계층화 분할이 필요하였다.

**분석:** Train·Validation·Test의 구매 비율이 유사한지 확인하고 의미를 1~2문장으로 작성합니다.  
Train·Validation·Test의 구매 비율이 각각 15.48%·15.46%·15.46%로 거의 같다. 세 분할 중 하나에 구매 구성이 치우쳐 들어가면 평가가 왜곡되어 공평하지 않다.

## 3. 구매 여부와 관련된 특성 분석 (CP-02)

- **방문자 유형(`VisitorType`)별 구매율:** Returning_Visitor 13.95% / New_Visitor 25.22% / Other 15.87%
- **구매율이 가장 높은 방문자 유형:** New_Visitor
- **구매·미구매 세션의 `ProductRelated` 중앙값:** 29.0 / 16.0
- **구매·미구매 세션의 `ProductRelated_Duration` 중앙값:** 1069.658 / 517.580
- **구매·미구매 세션의 `PageValues` 중앙값:** 17.543 / 0.000
- **구매·미구매 세션의 `ExitRates` 중앙값:** 0.015 / 0.029
- **특성 분석을 Train 데이터에서 수행한 이유:** Valid/Test의 관측치로 인하여 데이터 누수가 발생하지 않게 하기 위함이다.

**분석:** 구매 여부와 관련된 특성에서 관찰한 점과 `PageValues`의 예측 시점상 한계를 작성합니다.  
New_Visitor 구매율이 더 높다. PageValues는 구매 후에 가깝게 알 수 있는 정보라 예측 시점에 한계가 있다.

## 4. 데이터 전처리 및 PyTorch 입력 준비 (CP-03)

- **범주형 특성(One-Hot 인코딩):** Month, OperatingSystems, Browser, Region, TrafficType, VisitorType
- **수치형 특성(표준화):** Administrative, Administrative_Duration, Informational, Informational_Duration, ProductRelated, ProductRelated_Duration, BounceRates, ExitRates, PageValues, SpecialDay
- **이진 특성(변환 없이 사용):** Weekend
- **숫자로 표현된 코드값(`OperatingSystems`, `Browser` 등)을 범주형으로 처리한 이유:** 사용자 브라우저·운영체제 등은 범주이며, 숫자로 보여도 크기·순서 의미가 없는 코드라서 범주형(One-Hot)으로 처리한다.
- **`handle_unknown="ignore"`를 설정한 이유:** Valid/Test에 Train에 없던 범주가 들어올 수 있어, 알 수 없는 범주는 무시(해당 One-Hot을 0으로)하고 넘어가기 위함이다.
- **Train 전처리 전후 Shape:** (8630, 17) → (8630, 73)
- **Validation에 적용한 변환 기준:** Train에서 학습한 전처리 파라미터로 transform만 적용한다(다시 fit하지 않음).
- **PyTorch 입력·타깃 Tensor의 자료형 및 Shape:** float32 / 입력 (8630, 73), 타깃 (8630,)
- **`DataLoader` 배치 크기와 배치 수:** 256 / 34

**분석:** 신경망 입력을 `float32` Tensor로 준비하고 미니배치를 만드는 이유를 1~2문장으로 작성합니다.  
PyTorch 는 Numpy 를 그대로 처리할 수 없기에 Tensor로 변환한 후 미니배치로 쪼개어 나누어 업데이트한다.
