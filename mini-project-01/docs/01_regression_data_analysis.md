## 1. 데이터 탐색 (CP-01)

- **데이터 크기:** 17379행, 17열
- **결측값 및 중복 행:** 결측 0건, 완전 중복 행 0건
- **대여량(`cnt`) 분포의 특징:** 우측으로 치우친 횟수형 분포(왜도 약 1.28). 낮은 대여량 구간에 많은 시간이 몰리고, 높은 대여량은 상대적으로 드묾. 평균≪분산이라 단순 푸아송 가정보다는 과대산포에 가깝다.
- **평균 대여량이 높은 시간대:** 17시(약 461), 18시(약 426), 8시(약 359)

**분석:** 시간대별 대여량 그래프에서 발견한 특징을 1~2문장으로 작성합니다.  
심야·새벽(특히 3~5시)은 평균 대여량이 매우 낮고, 출근(8시)과 퇴근(17~18시)에 뚜렷한 쌍봉 피크가 나타난다. 수요가 시간대에 강하게 의존하므로 `hr`와 출퇴근 여부 특성이 중요하다.

## 2. 데이터 분할 및 누수 확인 (CP-02)

- **Train:** 2011-01-01 ~ 2012-05-25 / 12139건 / `cnt` 평균 159.72
- **Validation:** 2012-05-26 ~ 2012-09-11 / 2616건 / `cnt` 평균 281.04
- **Test:** 2012-09-12 ~ 2012-12-31 / 2624건 / `cnt` 평균 235.76
- **시간 순서로 분할한 이유:** 미래 수요 예측이 목적이므로, 임의 셔플보다 과거→미래 순 분할이 실전 평가에 가깝다. 같은 날짜의 행은 한 집합에만 넣어 일자 단위 누수도 막는다.
- **`casual + registered == cnt` 확인 결과:** 모든 행에서 True (항등식 성립)
- **누수 가능성이 있어 제외한 특성과 이유:** `casual`, `registered` — 정의상 `cnt`의 분해값이며 해당 시간이 끝나기 전에는 알 수 없음. `registered`–`cnt` 상관 약 0.97로 사실상 정답에 가까운 정보.

**분석:** 세 집합의 `cnt` 평균이 서로 다르다면, 그 차이가 이후 모델 평가에 어떤 영향을 줄지 1~2문장으로 작성합니다.  
Valid(약 281)·Test(약 236)의 평균 대여량이 Train(약 160)보다 높다. 분포·수준이 구간마다 다르므로 Validation/Test MAE는 Train보다 커질 수 있고, 단순 Train 점수만으로 일반화 성능을 판단하면 안 된다.

## 3. 상관관계 및 입력 특성 분석 (CP-02)

- **`temp`와 `cnt`의 상관관계:** 0.398 (양의 상관)
- **`hum`과 `cnt`의 상관관계:** -0.301 (음의 상관)
- **`windspeed`와 `cnt`의 상관관계:** 0.094 (약한 양의 상관)
- **`temp`와 `atemp`의 상관관계:** 0.992 (거의 동일 정보)
- **사용한 특성 목록(`FEATURES`):** `season`, `yr`, `mnth`, `hr`, `holiday`, `weekday`, `workingday`, `weathersit`, `temp`, `hum`, `windspeed` (선택 근거는 `adr.md` 의사결정 ①에 작성)

**분석:** 상관관계에서 알게 된 점과 상관계수만으로 특성을 결정할 수 없는 이유를 간단히 작성합니다.  
기온↑·습도↓일수록 대여가 늘어나는 경향이 있고, `temp`/`atemp`는 중복이라 하나만 쓰면 된다. 다만 `hr`·요일 같은 범주형은 선형 상관만으로 중요도가 잘 드러나지 않으며, 약한 `windspeed`도 다른 특성과의 교호로 도움이 될 수 있어 상관계수 절대값만으로 포함/제외를 단정할 수 없다.

## 4. 특성공학 및 전처리 (CP-03)

- **생성한 특성:** `is_commute_hour`
- **특성 생성 조건:** `workingday == 1` 이고 `hr ∈ {7, 8, 9, 17, 18, 19}` 이면 1, 아니면 0
- **범주형 특성 처리:** `season`, `mnth`, `hr`, `weekday`, `weathersit` → `OneHotEncoder(handle_unknown="ignore", sparse_output=False)`
- **수치형 특성 처리:** `temp`, `hum`, `windspeed` → `StandardScaler`
- **이진 특성 처리:** `yr`, `holiday`, `workingday`, `is_commute_hour` → `passthrough`
- **Train 전처리 전후 Shape:** (12139, 12) → (12139, 58)
- **Validation에 적용한 변환 기준:** Train에서 `fit`한 `ColumnTransformer`로 `transform`만 적용 (Valid로 다시 fit하지 않음)
